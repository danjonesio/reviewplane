# Contributing

## Before contributing

Read `AGENTS.md`, `docs/PROJECT.md`, `docs/PRODUCT.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md`.

## Contribution expectations

- Keep changes scoped and complete
- Preserve self-hosted operation
- Add tests for failure and denial paths
- Use shared protocol schemas
- Add an ADR for architecture changes
- Update documentation with behaviour
- Do not introduce mandatory telemetry or cloud services
- Do not weaken human acceptance or browser-control rules

## Commit and pull-request content

Explain:

- User problem
- Behaviour change
- Security and privacy impact
- Protocol or migration impact
- Test evidence
- Documentation changes

## Security issues

Do not open a public issue for a suspected vulnerability. Use the security contact defined for the repository once established.
